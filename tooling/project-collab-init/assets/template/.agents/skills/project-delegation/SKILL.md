# 项目子代理评估

每轮由主代理评估委派是否减少主窗口需要阅读的内容，并展示 `[x] 子代理评估：主窗口处理／委派内容，简短原因。` 勾选表示已评估，不表示必须派出代理。

## 触发与判断

按当前任务预计需要处理的材料评估：

| 条件 | 开始评估的阈值 |
|---|---|
| 实质阅读文件 | ≥4 个 |
| 阅读单份较长材料 | ≥300 行 |
| 修改文件 | ≥3 个 |
| 独立调查、审查或验证 | 无数量限制 |

文件名列表、搜索结果和简单定位不计为实质阅读；固定加载的规范入口不用于凑任务阈值。达到阈值后，确认任务可独立完成、验收边界明确，且简短结果足以支持主窗口下一步。紧密耦合、需要整体决策或仍须与用户澄清的任务留在主窗口。

## 派发

- 默认启动一个子代理；本轮主线程树中最多同时运行两个子代理，含下级代理。空闲工具槽位不提高此上限，更多任务排队。
- 默认使用独立上下文；支持 `spawn_agent` 时设 `fork_turns: "none"`，按 [派发模板](references/dispatch-template.md) 传必要信息。沿用主代理模型设置，具体技能要求模型选择时遵守其规则。
- 默认只读。实施任务指定允许修改的文件；并行写入范围互不重叠。进一步拆分由主代理决定，子代理先返回拆分建议。
- 主代理负责用户沟通、整体决策、结果整合、`tasks.md` 状态、项目记忆写入和最终验收。子代理提交完成证据与记忆候选。
- 把当前用户要求、适用记忆、项目规则和所用 OpenSpec 技能要求纳入任务包。对采用 `project-workflow` 的变更，进入 apply/archive 前仍由主代理在实际规划根目录运行 `node openspec/scripts/check-implementation-notes.mjs <change-name>`；其他 schema 遵守其本身的验收要求。委派不替代必要读取与检查。
- 子代理返回五项：**结论、证据位置、修改文件、验证结果、阻塞事项**。普通结果约 600 字；重要发现可展开并先写结论。未修改、未验证和无阻塞也明确注明。
- 主代理检查关键证据、实际变更和验证输出。仅“通过”不足以验收；工具不可用或委派收益低时说明原因，由主窗口处理。

目标是减少主窗口上下文占用；总 token 消耗可能增加。
