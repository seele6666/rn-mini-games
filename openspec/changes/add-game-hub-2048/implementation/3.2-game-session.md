# Implementation Note: 3.2 游戏会话与保存顺序

**Task:** 3.2 in ../tasks.md

## Requirement and dependencies

对应 `../specs/saved-game/spec.md` 的“自动保存当前局”和“安全恢复或新建游戏”，以及 `../specs/classic-2048/spec.md` 的首次 2048 提示。依赖任务 2.2 与 3.1。

## Files and interfaces

- `src/features/game2048/useGame2048.ts`：导出 `useGame2048()`，提供 `state`、`loading`、`saveError`、`winVisible`、`gameOver`、`move(direction)`、`restart()`、`continueAfterWin()`。
- `src/features/game2048/useGame2048.test.tsx`：用可控延迟的存储适配器测试加载、连续操作、失败后再次保存。必要时把顺序写入器拆到同目录的 `saveQueue.ts` 以便独立测试。

## Steps

1. 先验证加载完成前不处理移动，加载缺失或坏存档时只创建一局；重启后从 `hasWon` 恢复并不重复弹出胜利提示。
2. 连接纯规则引擎和存档读写。让每次有效状态变化按发生顺序入队保存，较早的异步写入不能覆盖较新的状态。
3. 保存失败时保留内存中可玩的状态并显示提示；下一次有效变化继续尝试保存。`restart()` 生成新局并覆盖旧存档。

## Verification

运行 `npm test -- --runInBand src/features/game2048/useGame2048.test.tsx`。用模拟的慢写入先后完成两次移动，预期最终存档是第二次移动后的状态；再在 Android 上关闭并重开验证恢复。

## Risks or handoff notes

从首页返回再进入会重新挂载游戏页，必须等待持久化写入顺序可靠。胜利弹窗是否显示是瞬时 UI 状态；已提示标记才属于存档。
