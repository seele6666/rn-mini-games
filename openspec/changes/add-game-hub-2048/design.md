# Design

## Context

项目目前只有 OpenSpec 目录和说明文件，没有 React Native 工程，也尚未初始化 Git。目标是供本人使用的 Android 单机小游戏集合，首个可玩游戏为 2048。具体需求见 `proposal.md` 和四份能力规格。

## Goals and non-goals

- 建立可继续添加游戏的首页导航，同时保持首版只有首页和 2048 两个界面。
- 将 2048 规则写成与 UI、存储无关的纯 TypeScript 函数，便于学习和测试。
- 在手机上离线运行独立 APK，恢复本机上一局。
- 首版不加入账户、服务器、联网排行、音效、撤销、棋盘尺寸设置或第二款游戏。

## Architecture and data flow

- 使用 Expo 默认 TypeScript 工程与 Expo Router。保留已有 OpenSpec 目录，先在临时子目录生成 Expo 工程，再把所需工程文件合并到当前项目根目录；不要覆盖 `AGENTS.md`、`.agents/`、`.codex/` 或 `openspec/`。以 `src/app/index.tsx` 作为首页，`src/app/games/2048.tsx` 作为游戏页，根布局使用简单的 Stack 导航。
- `src/features/game2048/engine.ts` 负责新棋盘、四方向移动、成对合并、得分、随机生成与可移动性判断。使用显式传入的随机数函数，测试可以给定确定性结果。初始两个数字出现在不同格子；每次生成新数字时按常见规则选择 2 或 4（默认 90% / 10%）。一次滑动只有在棋盘发生变化时才生成一个新数字。
- `src/features/game2048/storage.ts` 只负责读写一个带版本号的本地存档；使用 Expo 支持的 AsyncStorage。存档包括 4×4 棋盘、当前分数、是否已提示达到 2048。读取时验证棋盘尺寸、格子取值、分数和提示标记；损坏时返回“无有效存档”。
- `src/features/game2048/useGame2048.ts` 负责加载、操作和保存当前局。读取结束前，游戏页不接受滑动；有效移动或新局生成后按顺序保存，避免快速连续滑动让较旧的异步写入覆盖新状态。保存失败不清空内存中的棋盘，并给玩家可见的提示；下一次有效状态变化重试保存。
- 游戏页只负责布局、四向滑动和状态反馈。用 React Native 内置手势响应处理棋盘上的滑动；触摸距离达到阈值且主方向明确时才发出一次移动。胜利提示只在当前局首次生成 2048 时出现，“继续”保留棋盘；无可移动步时展示结束提示；重新开始需要确认。返回首页后再次进入同一局。
- `eas.json` 增加 Android APK 构建配置，使用 `android.buildType: "apk"`；`app.json` 设定固定应用标识。开发阶段可使用 Expo Go，交付验证使用独立 APK 在 Android 手机上离线运行。云构建需要 Expo 账号与构建时联网，安装后的核心游戏不需要联网。

## Decisions and alternatives

- **Expo Router**：默认 Expo 模板已包含导航，未来增加游戏可以增加路由；单组件切换页面虽然更少依赖，但会把游戏选择与页面生命周期耦合在一起。
- **纯函数规则引擎**：UI 只显示状态并发送方向输入；把移动规则写在组件内会让合并边界案例难以独立验证。
- **AsyncStorage 单份版本化存档**：数据量很小，无需数据库；只保留一局进度，不设计多存档槽位。所有状态写入同一个键，读取时只接受已知版本。
- **EAS APK 配置**：符合用户要求的独立安装包；Android 原生本地构建需要额外环境，首版先用 Expo 官方云构建流程。应用显示名暂定“小游戏合集”，Android 包名暂定 `com.seele.minigames`，如设备上已占用则在首次构建前调整。

## Risks and mitigations

- **快速滑动与异步保存顺序不一致** → 将保存操作串行化，并在规则单测与重启实测中核对最终棋盘。
- **无效或旧版存档导致崩溃** → 加版本与字段验证；验证失败时创建新局。
- **手势被页面导航或滚动抢占** → 仅在棋盘区域捕获明确方向的滑动，在 Android 真机上检查四向操作与返回键。
- **默认 EAS 构建产物是 AAB** → 明确设置 APK 构建类型，下载后在真机离线安装和启动验证。
- **现有目录非空、Expo 模板可能带演示文件** → 在临时目录生成后只合并所需文件，删除模板演示路由，验证原有 OpenSpec 工作流仍在。

## Verification approach

- 用 Jest 与 `jest-expo` 测试规则引擎：初始布局、四向压紧、一次合并、无效移动不生成、分数、胜利后继续及结束判定。
- 测试存档序列化和坏数据回退；在 Android 设备上手动检查退出、重启、恢复、重新开始与返回首页。
- 执行 TypeScript 检查和测试；运行 OpenSpec 校验，并通过 EAS 构建 APK。APK 安装后断网运行并复测核心流程。

## Open questions

无影响规格或任务拆分的未决问题。应用名称与包名可在第一次 APK 构建前按个人喜好修改；当前任务按上述默认值推进。
