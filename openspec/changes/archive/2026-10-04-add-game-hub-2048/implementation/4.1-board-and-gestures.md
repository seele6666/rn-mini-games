# Implementation Note: 4.1 棋盘界面与手势

**Task:** 4.1 in ../tasks.md

## Requirement and dependencies

对应 `../specs/classic-2048/spec.md` 的“创建经典棋盘”和“按方向移动和合并”。依赖任务 1.2 的路由和任务 3.2 的游戏会话。

## Files and interfaces

- `src/features/game2048/GameBoard.tsx`：接收 `board: Board` 和 `onMove: (direction: Direction) => void`，渲染 4×4 棋盘并把明确方向的滑动转成一次输入。
- `src/features/game2048/GameScreen.tsx`：为外层 ScrollView 创建 Native 手势，传入棋盘的 `scrollGesture`，让棋盘 Pan 在原生层阻止页面抢占触摸；根布局提供 GestureHandlerRootView。
- `src/app/games/2048.tsx`：展示分数、棋盘和加载态；调用 `useGame2048`。
- 可添加 `src/features/game2048/GameBoard.test.tsx`，测试 16 格渲染和方向判别；真机手势仍需人工验证。

## Steps

1. 使用 RN 基础组件布局，棋盘边长根据窗口宽度计算并限制最大值，确保窄屏能看到完整 4×4 棋盘；空格与数字方块有清晰区分。
2. 仅在棋盘区域通过 React Native Gesture Handler 的 Pan 捕获触摸，并阻塞外层 Native 滚动手势。手势正常结束时，根据位移阈值和主方向发出一次 `onMove`；取消、短距离及方向不明确的输入不移动。棋盘外的页面滚动保持可用。
3. 加载完成前显示占位，不允许移动。把有效移动后的 `state` 显示为棋盘和分数。

## Verification

运行 `npx tsc --noEmit` 和相关组件测试；测试真实原生手势事件到合并、计分和存档的路径，以及棋盘阻塞页面滚动的关系。在 Android 手机上实际向四个方向快滑、慢滑，预期棋盘按规则变化，轻触或距离不足的滑动不产生新方块，棋盘不被裁切；棋盘外仍能滚动页面。Jest 不模拟 Android 的原生抢占时序，不能替代该项真机复测。

## Risks or handoff notes

如果 RN 内置手势响应器在实测中与导航手势冲突，先定位冲突区域，再选择最小的兼容方案；不要为了一个棋盘引入整套动画系统。
