# Proposal

## Why

2048 的规则、会话、存储和界面已部分分离，但所有文件平放，页面还包含按钮与弹窗，棋盘同时处理手势生命周期。用规模较小且已验收的 2048 验证组织规范，便于后续整理斗地主。

## What Changes

- 开发者按 core、session、persistence、ui 定位文件，UI 按组件建立目录，测试就近存放。
- 页面与棋盘样式独立，棋盘复杂手势协调抽为 TS Hook，按钮与弹窗独立。
- 补充模块职责和依赖说明，保留现有注入入口及外部使用方式。
- 玩家可观察行为保持一致；没有新玩法、新依赖或发布版本变更。

## Capabilities

### New Capabilities

- `game2048-structure`：开发结构与兼容性约束，作为本次重构的技术验收依据。

### Modified Capabilities

无。正式 `classic-2048`、`saved-game` 与 `game-catalog` 的行为要求继续适用，不复制或修改其需求。

## Impact

影响 2048 源码、相邻测试、2048 路由的导入路径及模块说明。保留原存档键、版本、随机数调用顺序、手势关系与共享保存队列。当前分支存在未提交改动，本次就地迁移当前版本，不回退到 Git 基线；斗地主源码与制品保持原状。本轮不构建 APK，不归档变更。
