# Implementation Note: 5.1 回归与难度对照

**Task:** 5.1 in ../tasks.md

## Requirement and dependencies

依赖：2.4、3.3、4.3 及此前功能任务。对应 [doudizhu-opponents](../specs/doudizhu-opponents/spec.md) 的四档策略与 expert 牌力对照，以及所有规则、会话和首页规格。真机操作与响应时间交由5.3执行。保留1.1.0三档历史基准和构建记录。

## Files and interfaces

复用 `src/features/doudizhu/ai/expert-benchmark.test.ts`，更新 `docs/doudizhu-validation.md` 与根 `README.md`，保留原 `benchmark.test.ts` 的三档历史证据。新证据放 verification/doudizhu/v120，长对照使用明确环境开关。

## Steps

1. 执行全量TypeScript与Jest，修复斗地主和既有2048／首页回归，不删除失败案例或降低旧游戏要求。
2. 至少100个固定发牌种子，每种轮换目标策略的地主、上家农民、下家农民三个座次；其余电脑固定普通。hard 与 expert 使用相同牌与角色配对，合计至少600局。
3. 比较出牌能力时固定已确定地主的同一初始牌局，叫抢另以规则／策略测试验证；不要让角色选择差异掩盖出牌差异。
4. 记录各座次与总体胜率、配对改善/退步、非法动作、异常、未终局、节点和耗时、策略源码哈希。要求所有局合法终局，expert总体胜局严格多于hard；未达到则继续调优，保留失败报告。
5. 用800×360导出Web页面验证三手完整牌、独立横向浏览、20牌触达、设置暂停/恢复与按下反馈。设置、播放失败和生命周期通过专项测试，实际音频焦点及震动留真机。
6. 扩展真机清单，覆盖四档、旧三档存档、最近三手、离线音频、音量、开关、反馈、expert计算与2048。固定节点基准不代表手机耗时；expert端到端p95≤1.2秒，计算中返回≤100ms。

## Verification

执行 `npm run typecheck`、`npm test -- --runInBand`。显式基准在PowerShell中设置 `$env:DOUDIZHU_EXPERT_BENCHMARK='1'`，执行 `npm test -- --runInBand src/features/doudizhu/ai/expert-benchmark.test.ts`，结束恢复此任务环境变量。预期600局均合法终局、expert总体胜率高于hard，文档区分自动验证、Web检查和待测真机项目。

## Risks or handoff notes

不能把随机性导致的小批胜率波动或策略分支覆盖等同于确定的牌力排名。基准环境和预算必须一并记录；真实性能目标和体验证据在5.3。
