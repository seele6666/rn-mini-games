# Implementation Note: 1.1 实体牌与牌型规则

**Task:** 1.1 in ../tasks.md

## Requirement and dependencies

依赖：无。对应 [classic-doudizhu](../specs/classic-doudizhu/spec.md) 的“牌型与大小比较”，重点场景“连续牌型边界”“带牌模式及比较”“飞机翅膀边界”“四带二与炸弹区分”。遵循 [design](../design.md) 的规范化解释及结构化动作生成。

## Files and interfaces

新建 `src/features/doudizhu/types.ts`、`cards.ts`、`rules.ts`、`rules.test.ts`。实体牌包含唯一ID和点数；牌型描述包含种类、主体长度、主体点数、带牌模式。牌型分析返回合法解释集合，比较器接受目标牌型，生成器只接收当前玩家手牌及公开待压目标。

## Steps

1. 为54张牌与所有规格边界先编写表驱动案例，包括相同点不同花色、重复ID、空选择和非法主体。
2. 定义稳定实体ID、点数序和构造单副牌的函数，不用花色决定大小。
3. 实现主体与翼牌分离判定；明确对子单翼、双王限制、连续长度和2/王禁入连续主体。
4. 对领出和跟牌使用设计中的稳定解释次序，不能根据遍历偶然顺序改变结果。
5. 按点数计数组合生成合法动作，避免所有子集枚举；每个生成动作经比较器复验，等价花色选择稳定去重。

## Verification

执行 `npm test -- --runInBand src/features/doudizhu/rules.test.ts`。预期所有规则例子通过；非法牌型被拒；生成器输出都属于手牌且可合法打出；所有普通牌型与炸弹、王炸的关系一致。加入多种手牌和目标的生成／校验交叉检查。

## Risks or handoff notes

此处不实现叫抢、存档或UI。若发现规格未覆盖的合法解释歧义，先明确规则并同步设计，不能私自按第三方库规则替换本版本。完成状态仅更新 tasks.md。
