# Implementation Note: 5.3 Android真机验收

**Task:** 5.3 in ../tasks.md

## Requirement and dependencies

依赖：5.2。对应 [android-installation](../specs/android-installation/spec.md) 的“四档斗地主离线运行”“原生方向与后台恢复”，以及最近三手、配乐、反馈、设置、会话和首页场景。

## Files and interfaces

记录 `docs/doudizhu-validation.md`、必要的 `docs/android-validation.md` 追加回归记录。输入为5.2的明确APK版本及构建ID或APK SHA-256与5.1清单；用户已改为本地构建时使用实际APK哈希定位产物。用户曾报告Redmi K90 Max和OS 4.0.0.14；本次重新记录实际设备和Android主版本，不把OS版本号推断为Android版本。

## Steps

1. 安装正确新APK，优先从旧版同包名升级验证2048已有存档；关闭Metro、Expo Go和网络，验证冷启动。
2. 四档各完成叫抢和完整对局，覆盖真人地主与农民角色；结算只显示胜负，农民队友出完时真人也获胜。核验旧三档存档覆盖安装恢复。
3. 关闭系统自动旋转，验证首页→斗地主→首页→2048方向、系统返回、无栈回退、快速切换及后台恢复。
4. 在20张手牌、快速选取消及手牌浏览下验证触摸和安全区；非法牌、不出限制、提示确认、取消重开均符合规格。
5. 对叫抢／出牌／结束分别测试退出和重启恢复；电脑思考时切后台、回首页和确认重开，检查唯一提交、旧任务丢弃和存档隔离。
6. 最近三手覆盖不足三手、完整长组合、不出不占位、清轮移除待压、重发清空与恢复重建；20牌仍能独立浏览点选。
7. 断网验证内置音乐循环、默认音量与恢复、路由/后台/音频焦点暂停、快速往返和失败重试；验证设置暂停AI与提示，音乐/震动开关保存；取消、浏览和禁用不误震。
8. 按5.1取数方式分别记录困难计算与expert端到端响应；expert p95≤1.2秒，正常负载计算中返回≤100ms。没有设备数据则仍未测。
9. 失败项形成具体复现、修复和复测记录；逐项实际通过后才更新tasks.md完成状态。

## Verification

设备、Android版本、1.2.0/code4 APK哈希、步骤和实际结果齐全；每个清单项是通过、失败或未测之一。四档、最近三手、音频反馈、方向、恢复、20牌交互、性能及2048回归均完成验证才可结束任务。

## Risks or handoff notes

浏览器、模拟单元测试或构建结果不能代替独立APK真机。若仅用户能够操作手机，等待其真实反馈，准确保留未测任务，不因此提前归档。
