# Implementation Note: 1.2 发牌与有限叫抢

**Task:** 1.2 in ../tasks.md

## Requirement and dependencies

依赖：1.1。对应 [classic-doudizhu](../specs/classic-doudizhu/spec.md) 的“三人发牌与地主底牌”“有限叫地主与抢地主流程”，覆盖“新局发牌”“无人叫地主”“有人叫但无人抢”“首次叫者反抢”“已不叫玩家跳过抢阶段”。

## Files and interfaces

新建 `src/features/doudizhu/engine.ts`、`engine.test.ts`，扩充 `types.ts`、`cards.ts`。提供 `createGame`、`getLegalActions`、`applyAction`；注入洗牌随机源。动作携带座位、gameId、dealId、revision。

## Steps

1. 写不同起叫座位与叫／不叫分支测试，再实现17/17/17＋3发牌和初始 calling 状态。
2. 首次叫之后构造抢资格与行动队列，跳过曾不叫者；其他人各一次，有抢才给首次叫者最后反抢机会。
3. 无人抢或抢队列耗尽时确定唯一地主，公开并仅加入一次底牌，再进入 playing。
4. 全不叫创建新dealId，清理本次历史与选择、重新发牌并顺延起叫者；gameId保持同一会话，revision维持递增，并保存当前deal的initialRevision供恢复重放。
5. 每次转换记录可重放的有效动作，拒绝旧阶段、旧revision、非轮到者的选择。

## Verification

执行 `npm test -- --runInBand src/features/doudizhu/engine.test.ts`。覆盖三起叫座位的叫抢分支；每次发牌54张唯一，地主确定后20/17/17；不叫者不可抢；首次叫者只有一次最后反抢；没有无限抢循环，重复提交底牌不会重复加入。

## Risks or handoff notes

全部不叫可以再次发牌，但不能以强制分配地主绕过规则。测试重发前后的dealId、历史与底牌，而不是只断言地主最终存在。不增加倍率或积分字段。
