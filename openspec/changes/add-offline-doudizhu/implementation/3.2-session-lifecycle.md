# Implementation Note: 3.2 会话与生命周期

**Task:** 3.2 in ../tasks.md

## Requirement and dependencies

依赖：2.3、3.1。对应 [doudizhu-session](../specs/doudizhu-session/spec.md) 的“新局难度与确认重开”“暂停电脑与唯一恢复行动”“安全恢复与写入失败反馈”，以及 [doudizhu-opponents](../specs/doudizhu-opponents/spec.md) 的“思考期间离开或重开”“使用提示”。

## Files and interfaces

新建 `src/features/doudizhu/useDoudizhu.ts`、`useDoudizhu.test.tsx`。注入存储、电脑／提示策略、时钟和随机源。hook接收页面focus，监听AppState，返回可见状态、权限、动作、选牌建议及存档反馈。

## Steps

1. 先用可控Promise和假的生命周期事件测试恢复加载、失焦／后台取消和旧计算迟到。
2. 恢复完成且页面focused、应用active时才启动电脑；为gameId/dealId/revision/seat维护唯一任务和generation。
3. 计算提交前复核当前身份与标识；重复effect或前台事件不重复提交。提示使用独立任务，改变回合后清除旧建议。
4. 每次合法转换提交不可变存档快照；错误提示反映最新成功保存情况，旧失败回调不得覆盖较新成功反馈。
5. 重开确认取消保留原局；确认后停止旧任务，选择难度并写新gameId。返回／卸载后仍让已排队写入完成，但不运行电脑。
6. finished恢复只显示结果，真人等待无自动代打。

## Verification

执行 `npm test -- --runInBand src/features/doudizhu/useDoudizhu.test.tsx`。覆盖后台不推进、恢复电脑只提一次、快速卸载重挂载、旧AI／提示污染新局、重开取消、写入失败及后续成功清除提示。用历史长度与revision断言真实提交次数。

## Risks or handoff notes

取消计算和丢弃结果均需实现：不能只清定时器而允许已经开始的计算提交。读失败、损坏与缺失按3.1的分类显示。新局未真正提交前不删除可恢复旧存档。
