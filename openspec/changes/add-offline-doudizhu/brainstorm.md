# Brainstorm

## 2026-10-22 已批准的体验升级

用户明确要求实施对话中的完整升级计划：全桌最近三手完整出牌（非各玩家最近一手）、非常困难expert（约一秒、公平离线）、Monkeys Spinning Monkeys替代配乐、视觉与可关闭的轻震动，不加入操作音效。继续本变更，旧1.1.0证据保留，新增任务并重新执行综合验证、1.2.0/code4本地ARM64构建，真机项目待实际反馈。

最近三手仅取当前deal的有效play历史，按时间从左到右，完整展示玩家、牌型和牌面，各区可横向浏览；不出不占位，清轮仅清待压标记，重发清历史，存档恢复重建。设置独立保存musicEnabled=true、volume=.25、hapticsEnabled=true，背景/离页/音频焦点丢失暂停，失败可重试；设置面板暂停电脑与提示。专家初始800ms/3200节点/8候选/12轮采样/24步/80000工作单元，8ms分片，180ms行动节奏，原困难参数保留，困难与专家至少100种子×3座次配对且专家总体胜局更多。真机专家端到端p95≤1.2s、返回≤100ms。

## Goal and audience

在个人 Android 小游戏合集里增加基础三人斗地主，让用户自己离线游玩，同时作为 Expo / React Native / TypeScript 学习作品。真人固定占一个座位，其余两个座位由电脑控制；真人既能当地主，也能当农民。

## Known constraints

- 现有项目使用 Expo 57、Expo Router、React Native、TypeScript、AsyncStorage；首页和 2048 已实现并完成首版验收。
- 首页 `src/app/index.tsx` 目前固定展示一个 2048 入口。路由和游戏逻辑分别放在 `src/app/`、`src/features/`。
- `app.json` 当前全局为 portrait，根 Stack 未指定页面方向；必须为斗地主增加页面方向策略。
- 现有 `saved-game` 正式规格和存储字段只覆盖 2048。斗地主使用独立能力和独立存档键，不把它泛化成所有游戏的存档格式。
- 本次只生成规划制品。真机横屏、困难档耗时、独立 APK 离线恢复须在 apply 阶段实际验证。

## Options considered

1. TypeScript 规则与启发式策略：与现有技术栈一致，便于学习、单元测试和离线运行，作为首版基础。
2. 有预算的未知牌采样与模拟：适合在困难档增加决策能力，须限制计算量并验证农民合作、实际胜率和设备响应。
3. DouZero 等预训练模型：可作为未来升级，但原版主要负责出牌，还涉及输入编码、权重转换和本地运行时适配，不作为本次依赖。

## Confirmed decisions

以下为用户在本次探索与提案对话中明确选择的内容：

| 决策 | 用户来源 |
|---|---|
| 基础三人斗地主，另外两位由程序控制且可选难度 | 最初请求：“最基础的三人斗地主。另外两个用智能程序或者别的什么方案，可以选择难度。” |
| 完全离线 | 离线条件问题答复：“完全离线可玩（推荐）” |
| 叫地主／抢地主 | 叫牌方式答复：“叫地主／抢地主” |
| 自动保存未结束对局，下次继续 | 存档问题答复：“对” |
| 简单、普通、困难；困难增加有限模拟推演 | 三档方案答复：“接受” |
| 斗地主横屏，首页和 2048 保持竖屏 | 屏幕方向问题答复：“横” |
| 首版只显示地主／农民胜负 | 2026-10-13 结算问题答复：“仅显示胜负（推荐）” |

### 提案采用的规则细则

以下是为可实施、可测试而选定的首版固定规则版本，用户尚未逐条确认；属于本提案供审阅的细则，不称为用户原话。

- 单副 54 张无癞子牌；花色只区分实体牌，不影响大小。固定座次按 0→1→2→0 行动，真人为 0。
- 起叫者首局随机，全部不叫后重新发牌并把起叫座位顺延一位。叫牌阶段各人一次叫／不叫，出现首次叫地主即进入抢阶段。
- 此前不叫的玩家不能抢；其余非起叫者按座次各抢／不抢一次。如果有人抢，首次叫地主者最后再获得一次抢／不抢机会；最后抢者当地主，没有抢者则首次叫者当地主。
- 采用常见完整牌型。飞机带单允许对子作为两张单牌，主干之外的同点单翼最多两张；单翼不同时带双王。四带二单张允许带一对，但不同时带双王。飞机带对和四带两对的各对点数不同。所有翼牌与主体点数不同。
- 三张可以不带牌；飞机可以不带翅膀。顺子至少五张、连对至少三对、飞机至少两组三张，连续主体不含 2 和王。
- 真人没有出牌倒计时，避免学习和思考时被自动代打。新局选择难度；恢复沿用原难度，修改难度通过确认重新开局完成。
- 只结算阵营胜负，不增加积分、倍率、春天奖励、金币、账号或排行榜。炸弹与王炸仍参与牌型比较。
- 提供选牌、出牌、不出、提示、返回首页和确认重开。提示基于当前难度和玩家可见信息，最终仍由玩家确认出牌。

## Open questions

没有阻止提案生成的范围问题。牌型细则和叫抢轮次已经作为固定首版规则写明，供实施前审阅；如用户修改，需同时修订规格、设计和任务。

可以在不改变需求范围的情况下调整的细节：牌面颜色、角色名称、动画时长和困难搜索的具体参数。困难档是否足够有挑战性由固定种子对局及真机预算测试决定，不能用等待更久代替难度验证。
