# 项目记忆

每轮由主代理展示 `[x] 记忆评估：应用记忆编号及原因／无相关记忆／适用，需加载索引。` 勾选表示完成适用性评估；尚未读取的条目不能声称已应用。子代理提交候选和来源，由主代理统一核验与写入。

## 读取

新会话先读项目根目录 `memory/index.md`，再按任务读取有效且范围适用的条目；后续复用已加载内容，任务变化或文件更新时重新检查。无需加载所有记忆、游戏规格或归档。候选用于观察；已替代的条目只用于追溯。

## 沉淀

| 用户表达 | 处理 |
|---|---|
| 明确的长期要求 | 立即写入有效记忆 |
| 单次隐含偏好 | 写入候选，记录一个真实来源轮次 |
| 同一含义、同一范围的偏好在两个不同用户轮次出现 | 自动转为有效记忆，保留两份来源并移除候选副本 |
| 临时要求，如“这次答案简短” | 当前任务执行，不升级为长期规则 |
| 举例、引用、助手复述、无用户来源的代理推断 | 不作为偏好证据 |

同一句在一个消息里出现多次仍算一个轮次；重新读到旧来源不增加次数。两个临时要求也不会变成长期偏好。来源无法区分时保留候选，不编造重复证据。

写入时读取 [条目模板](references/memory-entry-template.md)，先按含义与范围检索偏好和候选文件，更新已有条目。编号在两个文件之间唯一；迁移保留编号、原话与日期。一次明确长期要求的出现次数可为 1。普通记忆更新只改数据，不改技能流程。

## 更新与冲突

- 新的明确长期要求覆盖旧记忆：旧条目标记“已替代”并关联新编号，新条目设为有效；同步调整候选与 `index.md`，避免旧偏好再次晋升。
- “这次例外”只覆盖当前任务，保留长期条目；范围不同的要求分别记录。含义或范围不清且影响任务时，先请求澄清。
- 自动维护记忆内容；技能流程仅在用户明确提出改进要求时调整，并按技能编写流程验证。
- 本项目用户已授权在项目根目录 `memory/` 按上述条件自动维护记忆，无需逐条确认。写入仍以当前模式和权限允许为前提；规划或只读模式下把待沉淀内容留在本轮回复，说明尚未落盘，允许修改后再写入。

## 存放与使用

- `memory/index.md` 约 30 行，保存范围与有效记忆索引；内容增长时按范围分组并保留查找入口，避免遗漏适用规则。
- `memory/preferences.md` 保存有效与已替代的长期要求；`memory/candidates.md` 保存待观察条目。只维护需要使用的简短记录，不保存完整聊天日志。
- 记忆作用于本项目，不修改全局 Codex 记忆或配置。以当前用户要求为准，同时遵守更高优先级指令；记忆不会扩大执行授权。
- 游戏正式行为以 `openspec/specs/` 为准，OpenSpec 任务状态以对应 `tasks.md` 为准。涉及项目事实时引用其权威文件，使用前核实可能变化的事实。
