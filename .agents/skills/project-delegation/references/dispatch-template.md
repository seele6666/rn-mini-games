# 派发与返回模板

实际委派时填写与该任务相关的部分，路径指向当前工作区。子代理只接收任务所需背景；需要材料时自行读取指定来源。

```text
角色：只读调查／审查／验证，或指定范围的实施。
工作区：<项目根目录绝对路径>
目标：<一个可独立验收的结果>
必要背景：<已确认的事实、当前用户要求、适用记忆编号及规则>
规范：读取 AGENTS.md 和 <本任务相关技能或规范路径>；遵守其中适用要求。
输入：<需要读取的路径、问题、已知验证结果；不粘贴完整聊天>
允许修改：无（默认）／<明确的文件路径清单>
并行边界：<其他代理处理的范围与本任务不能写入的共享文件>
验收标准：<结果应解决什么问题，需要哪些证据或验证>
OpenSpec：<适用变更名、制品路径、必要读取；不适用则省略本行>
协作：需要澄清、扩大范围或继续拆分时先向主代理报告。
        主代理统一维护 tasks.md、项目记忆并对用户汇报。
返回：结论、证据位置、修改文件、验证结果、阻塞事项。
      普通结果约600字；重要发现先写结论再展开。不附整段日志。
```

返回示例：

```text
结论：恢复存档时未检查棋盘尺寸，损坏数据可能导致页面异常。
证据位置：src/features/game2048/storage.ts:42（假想测试路径）。
修改文件：无，只读审查。
验证结果：静态检查已完成；未运行真机验证。
阻塞事项：需主代理确认异常数据的处理策略。
记忆候选：无。
```

“记忆候选”仅在有真实用户来源时附加；测试案例和假想路径属于示例，不写入项目记忆。
